# Focus ST — Project Context

## What this is
A connected system of record for a 2017 Ford Focus ST (2.0L EcoBoost, MT82 6-speed,
MK3). Three surfaces share one source of truth — **the GitHub repo is the database.**

1. **Parts PWA** (`web/index.html`) — single-file vanilla HTML/CSS/JS, no build, no
   framework. Reads/writes `data/PARTS.md` and `data/MODS.md` directly on GitHub via
   the Contents API, using a fine-grained PAT stored in the browser's `localStorage`.
2. **Garage HUD** (`web/garage.html`) — motorsport dashboard; hydrates from
   `web/garage.json`.
3. **Digital Garage** (`digital-garage/`) — Postgres + FastAPI + MCP truth store that
   exports `web/garage.json` and `data/MODS.md`. Its own `digital-garage/README.md`
   documents it.

## The three tabs (in `web/index.html`)
1. **Add** — form (name, category strip, subcategory strip, URL, notes). Submitting
   appends a line under `## Wishlist` in `data/PARTS.md`.
   ⚠️ **The category/subcategory pills are cosmetic**: `injectLine()` always appends to
   `## Wishlist` (creating it if missing); the category is only saved to `localStorage`
   and shown in "Recent". The `CATS` taxonomy (Performance / Exterior / Interior /
   Maintenance) is **separate** from the catalog section names in `PARTS.md`.
2. **Garage** — browses the `data/PARTS.md` catalog. Parses each
   `<details><summary><b>SECTION</b>` into slots (`#### Slot`), shows the installed part
   + condition emoji. Tapping a slot opens the upgrade sheet; confirming rewrites that
   slot's `**Installed:**` line and marks it `<!-- MOD -->`.
3. **Mods** — filtered view of slots carrying `<!-- MOD -->`. Each install regenerates
   `data/MODS.md`.

## PARTS.md format (matters — the parser depends on it)
**Catalog** (hand-authored, drives Garage + Mods):
```markdown
<details>
<summary><b>SECTION NAME</b></summary>
<br>

#### Slot Name *(optional spec note in italics)*
**Installed:** [Part Name](url) — OEM · PART-NUM · ⚠️ unknown

<details>
<summary>Upgrade</summary>

| Tier | Part | # | ~Price | Notes |
|------|------|---|--------|-------|
| OEM | [Stock part](url) | PART-NUM | ~$15 | ... |
| Performance | [Upgrade](url) | — | ~$55 | ... |

</details>

---
</details>
```
Parser rules to preserve:
- Sections detected by `<summary><b>...</b></summary>`.
- Slots are `#### ` headings; base name is everything before ` *(`.
- `**Installed:**` line: a `[name](url)` link is extracted if present; condition is the
  first emoji among `✅` / `🔧` / else `⚠️`.
- `<!-- MOD -->` on the `**Installed:**` line = "changed from stock" (shows in Mods).
- Upgrade table's first column is the tier; a row whose tier is exactly `OEM` is the
  stock reference. Header rows (`Tier` / `Tool` / `Item`) are skipped.

**Wishlist** (app-appended): a `## Wishlist` section of `- [ ] [name](url) — notes`
lines, created lazily on first Add.

## GitHub sync internals (PWA)
- Auth: `token` header with a PAT needing **Contents: read & write** on `2smok3d/focus-st`.
  `OWNER`/`REPO` and the paths `PARTS_PATH='data/PARTS.md'` / `MODS_PATH='data/MODS.md'`
  are constants at the top of the `<script>` in `web/index.html`.
- Reads/writes go through `ghGet` / `ghPut` (Contents API, base64).
- **SHA cache:** `localStorage` `{sha, content, ts}`, 5-min TTL. Writes reuse the cached
  SHA; on `409` the cache clears, refetches, retries once.
- **Install flow** (`doInstallPart`): update PARTS.md slot → PUT → regenerate + PUT
  MODS.md (a MODS.md failure is non-fatal).

### localStorage keys
`fst_tok` · `fst_cache` · `fst_hist` (last 8 adds) · `fst_cat` · `fst_sub`.

## Web Share Target
`web/manifest.json` registers a GET share target → `index.html?url=…&text=…&title=…`.
`cleanTitle()` strips retailer boilerplate (Amazon, eBay, …) from the shared title.

## Service worker (`web/sw.js`)
Cache `fst-v2`, precaches the shell (`index.html`, `garage.html`, `manifest.json`,
`icon.svg`), network-first with cache fallback, **explicitly skips `api.github.com`**.
Bump `CACHE` when shipping shell changes.

## digital-garage coupling
`python -m app.cli export` (and auto-export after any approval) writes:
- `web/garage.json` — the dashboard's live feed
- `data/MODS.md` — human-readable changes-from-stock

If you move these paths, update `digital-garage/app/export.py` and
`.github/scripts/validate_garage_json.py` together.

## Conventions
- Web files are single-file, no build, no npm; match the terse vanilla style.
- **Design system:** black `#0a0a0b`, ST red `#e8000d`, Chakra Petch / IBM Plex Mono
  (system fallbacks), mobile-first, safe-area aware. Self-contained — no CDNs/external
  assets.
- HTML injected via template strings is escaped with `esc()`.

## Dev server
```powershell
pwsh -File web/serve.ps1     # → http://localhost:3000 (serves web/index.html)
```
No build. (Web Share Target + installability need HTTPS, so those only fully work on
the deployed Pages site.)

## Deployment
GitHub Pages, `master` branch root serves the whole tree — the apps live at
`/focus-st/web/…`, the landing at `/focus-st/`. Push to deploy; no build. Bump `CACHE`
in `web/sw.js` when changing shell files. The `digital-garage` backend runs locally
(Docker), not on Pages.
